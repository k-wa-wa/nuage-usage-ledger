# 使用量勘定システム 設計 (たたき台)

クラスタの資源使用量を、勘定として記帳・残高管理するシステムの設計である。
現在の日次使用量帳票 (README) を発展させ、このリポジトリで一体として扱う。

## 1. 目的と方針

### 1.1 目的

- namespace・ホストごとに、資源の**割当**と**使用**を記帳し、**残高** (割当の残り) を管理する
- 使用量を共通の単位に換算し、日次で締めて元帳を更新する
- 割当の超過を検知し、通知する

課金はしない。単位は金銭ではなく、資源の換算単位である。

### 1.2 方針

- **勘定系の作法を真似る。** 業務日付、日次締め、元帳の世代管理、複式の仕訳、試算表による貸借一致の検証、統制勘定と補助元帳の照合、端数処理規則の明文化などを、このシステムの規模には過剰と承知のうえで取り入れる。目的は、メインフレームの勘定系の設計と運用を体験し、理解することにある
- 処理はメインフレーム (MVS) の中で完結させる。時刻 (ZTIMER)・データ取得 (REXX)・集計と記帳 (SORT・COBOL)・帳票の印字を MVS が持つ。Linux 側は帳票の PDF 化だけを担う
- マスタ (換算表・勘定・割当) は Git で宣言し、nuage-cluster の mvs-config で MVS に届ける。MVS の中の手作業での変更はしない

## 2. 決定事項

| # | 論点 | 決定 | 理由 |
| :-- | :-- | :-- | :-- |
| 1 | 単位 | 資源ごとの使用量を、共通の換算単位 **RU (Resource Unit)** に換算して記帳する | 残高を 1 つの数で表せる。換算と端数処理が勘定系の 10 進演算の題材になる |
| 2 | 換算表 | 仮の値で始め、Git で管理する (3 章) | 値の妥当性は運用しながら調整する |
| 3 | 勘定の単位と番号 | namespace・ホスト 1 つにつき 1 勘定。勘定番号は「区分コード 3 桁 + 連番 7 桁」 | 現在の帳票の 1 行と同じ粒度にする |
| 4 | 割当 | **週次**。毎週月曜の業務日付で、勘定ごとの割当額を一括で記帳する | 日次より変化を細かく追え、月次より残高の推移に意味が出る |
| 5 | 残高不足 | マイナス残高を許し、**超過通知**を出す | 使用は実際に発生した事実であり、記帳を拒否できない |
| 6 | 処理日 | 毎日処理する (休日の概念は持たない) | 営業日カレンダーは後の題材にする |
| 7 | 端数処理 | RU の 1 未満を**切り捨てる** (明細行ごと) | 規則を 1 つに決めて明記することを優先する |
| 8 | 置き場所 | このリポジトリで一体として扱う。名前は `nuage-usage-ledger` (旧 nuage-usage-report) | 使用量の帳票と勘定は同じ業務領域である |

## 3. 単位と換算表

| 資源 | 使用量の単位 | 換算 (RU) |
| :-- | :-- | :-- |
| CPU | コア時間 | 1 コア時間 = 10 RU |
| メモリ | GB 時間 | 1 GB 時間 = 1 RU |
| 通信 | GB | 1 GB = 2 RU |
| ストレージ | GB 日 | 1 GB 日 = 0.5 RU |

- 使用量は小数第 2 位まで持つ (現在の固定長レコードと同じ `9(7)V99`)
- 換算額 = 使用量 × 換算率。資源ごとに計算し、**1 RU 未満を切り捨てる**。勘定の日次使用額は、切り捨て後の資源ごとの額の合計とする
- 換算表は有効開始日を持ち、改定しても過去の記帳は当時の換算率のまま残す

## 4. 勘定の体系

### 4.1 勘定科目 (総勘定元帳)

| 科目コード | 科目 | 意味 | 残高の向き |
| :-- | :-- | :-- | :-- |
| 1100 | 割当原資 | 割り当てた RU の出どころ | 借方 |
| 2100 | 利用者勘定 (統制勘定) | 各勘定の残高の合計。明細は補助元帳 (4.2) が持つ | 貸方 |
| 4100 | 使用実績 | 使用した RU の累計 | 貸方 |

### 4.2 補助元帳 (勘定マスタ)

利用者勘定の明細として、勘定ごとの残高を持つ。

| 項目 | 内容 |
| :-- | :-- |
| 勘定番号 | 区分コード 3 桁 + 連番 7 桁 (例: `100-0000001`) |
| 区分コード | `100` = K8S (namespace)、`200` = HOST (NixOS ホスト) |
| 名称 | namespace 名またはホスト名 |
| 週次割当額 | 毎週月曜に記帳する RU |
| 残高 | 割当累計 − 使用累計 (マイナスもある) |
| 最終取引日 | 最後に記帳した業務日付 |

勘定の追加・廃止・割当額の変更は、Git の勘定マスタ定義で宣言する。

### 4.3 仕訳

| 取引 | 借方 | 貸方 |
| :-- | :-- | :-- |
| 週次割当 | 1100 割当原資 | 2100 利用者勘定 (該当勘定の残高を増やす) |
| 日次使用 | 2100 利用者勘定 (該当勘定の残高を減らす) | 4100 使用実績 |

### 4.4 検証 (締めのたびに行う)

- **試算表の貸借一致**: 全科目の借方合計 = 貸方合計
- **統制勘定と補助元帳の照合**: 2100 利用者勘定の残高 = 勘定マスタの残高の合計
- **未登録の利用者**: 使用量があるのに勘定が無い namespace・ホストは、記帳せず未登録リストに出す

不一致があれば、そのジョブを異常終了させ、その日の締めを確定させない。

## 5. データ

すべて `NUAGE.USAGE.*` に置く。高位修飾子 NUAGE の別名はユーザーカタログ UCPUB000 を向く (nuage-cluster が作る)。

| データセット | 中身 | 形式 |
| :-- | :-- | :-- |
| `NUAGE.USAGE.BIZDATE` | 業務日付管理。1-8 桁目 次回処理日、10-17 桁目 最終締め日 (YYYYMMDD) | 順編成 FB 80 |
| `NUAGE.USAGE.CNTL(RATES)` | 換算表マスタ (Git で宣言) | PDS メンバー FB 80 |
| `NUAGE.USAGE.CNTL(ACCTDEF)` | 勘定マスタ定義 (Git で宣言) | PDS メンバー FB 80 |
| `NUAGE.USAGE.MASTER` | 勘定マスタ (補助元帳)。勘定ごとに 1 レコード | GDG (35 世代) FB 100 |
| `NUAGE.USAGE.GL` | 総勘定元帳。科目ごとに借方・貸方の累計 | GDG (35 世代) FB 80 |
| `NUAGE.USAGE.JOURNAL` | 仕訳。締め 1 回分ずつ世代として残す (追記のみ) | GDG (35 世代) FB 80 |
| `NUAGE.USAGE.GDGMODEL` | GDG の世代を作るときの型紙 (MVS 3.8j で必要) | 順編成 (空) |

- 元帳は「旧世代 `(0)` + 当日の取引 → 新世代 `(+1)`」で更新する。前日の世代が残るため、任意の締めの状態に戻せる
- 数値の内部表現: ジョブ間で受け渡すレコード (使用量・取引・仕訳) はゾーン 10 進 (表示形式。目で読める)、元帳の金額 (残高・累計) は符号付きのパック 10 進 (`S9(11) COMP-3`)

### 5.1 レコード

| レコード | 桁 | 内容 |
| :-- | :-- | :-- |
| 使用量 (REXX → TRANGEN) | 1-8 / 9-13 / 14-37 / 38-73 | 日付、区分、名前、使用量 4 種 (`9(7)V99`) |
| 取引 (TRANGEN → POSTING) | 1-10 / 11-18 / 19 / 20-55 / 56-64 / 65-88 / 89-93 | 勘定番号、日付、種別 (A 割当 / U 使用)、使用量 4 種、換算額 (RU)、名前、区分 |
| 勘定マスタ | 1-10 / 11-15 / 16-39 / 40-57 / 58-65 / 66-73 / 74 | 勘定番号、区分、名称、残高・割当累計・使用累計 (各 `S9(11) COMP-3`)、開設日、最終取引日、状態 (A 定義あり / U 定義なし) |
| 総勘定元帳 | 1-4 / 5-20 / 21-26 / 27-32 | 科目コード、科目名、借方累計・貸方累計 (各 `S9(11) COMP-3`) |
| 仕訳 | 1-8 / 9-14 / 15-18 / 19-22 / 23-32 / 33 / 34-44 | 日付、連番、借方科目、貸方科目、勘定番号、種別 (O 開設時割当 / A 割当 / U 使用)、金額 |

## 6. 処理

### 6.1 日次締め (ジョブ LEDGER。毎日 06:10、ZTIMER から起動)

```
 GET      REXX : 業務日付を読み、次回処理日から前日までの使用量を VictoriaMetrics から取る
                 前日まで処理済みなら RC 4 で終わり、後続はすべて飛ばす
 TRANGEN  COBOL: 換算表で RU に換算し (1 RU 未満切り捨て)、使用の取引を作る
                 期間内の月曜ごとに、全勘定の週次割当の取引を作る
                 勘定の無い利用者は未登録リストに印字する
 SORT          : 勘定番号・日付・種別の順
 POSTING  COBOL: 勘定マスタ定義・旧勘定マスタ(0)・取引を勘定番号で突き合わせて記帳する
                 定義にあってマスタに無い勘定は開設し、週次割当額を 1 回分 (開設時割当) 記帳する
                 試算表の貸借一致と、統制勘定と補助元帳の照合を検証する (不一致なら RC 16)
                 勘定残高明細・超過通知・試算表を印字する
 CMASTER / CJOURNAL / CGL / CBIZDATE
               : 確定。ここまでがすべて RC 0 のときだけ、新しい世代と次回処理日を書き込む
```

- POSTING までの成果物は一時データセットに作り、最後の確定ステップでまとめて書き込む。検証に失敗した締めは何も確定しない
- 止まっていた日があっても、GET が次回処理日から前日までをまとめて取り、日付順に記帳する (遡り処理)
- 失敗しても業務日付は進まないので、同じジョブを再実行すればよい
- 初回 (業務日付が空) は前日から始める。GET の `START=YYYY-MM-DD` で始める日を指定できる

### 6.2 日次使用量明細 (ジョブ USAGERPT。毎日 06:00)

元帳とは別のジョブとして、前日の使用量そのものを帳票にする (GET → SORT → COBOL)。

## 7. 帳票

すべて帳票プリンタ (出力クラス M) に印字し、nuage-cluster のプリンタ役が PDF にする。

| 帳票 | ジョブ | 内容 |
| :-- | :-- | :-- |
| 日次使用量明細 | USAGERPT | 区分・名前ごとの使用量と、区分ごとの小計 |
| 未登録リスト | LEDGER (TRANGEN) | 勘定の無い利用者の使用量 |
| 勘定残高明細 | LEDGER (POSTING) | 勘定ごとの前日残高・割当・使用・残高。超過は `*`、定義なしは `U` |
| 超過通知 | LEDGER (POSTING) | 残高がマイナスの勘定 |
| 試算表 | LEDGER (POSTING) | 科目ごとの借方・貸方の累計と残高、検証の結果 |

## 9. 決めたこと (旧未決事項)

| 論点 | 決定 |
| :-- | :-- |
| 換算表と割当額 | 換算表は 3 章の値。割当額は 2026-10-21 の実績の 1 週間分に 2 割の余裕を足し、100 RU 単位に切り上げた (`mvs/cntl/ACCTDEF`) |

## 10. 実装で分かったこと

| 項目 | 内容 |
| :-- | :-- |
| COBOL の WRITE | ブロック化した出力ファイルは、WRITE の後で記録域が次のレコードに移る。WRITE したレコードを後で参照すると S0C7 (データ例外) になる。レコードは WORKING-STORAGE で組み立てて `WRITE ... FROM` で書く |
| COBOL-68 | 部分参照 (`X(1:1)`) が無い。FD に 01 を複数書くと同じ記録域を別の形で見られる |
| 権限とカタログ | 利用者指定なしのバッチ (内部リーダ経由) は既定の権限で動く。マスターカタログは更新できず、GDG の世代のカタログ登録に失敗する (`NOT CATLGD 2`)。しかも確定ステップの RC は 0 のままである。NUAGE の別名をユーザーカタログ UCPUB000 に向け、RAKF で `NUAGE.USAGE.*` に ALTER を許して解決した (`mvs/rakf`) |
| HTTP の接続数 | BREXX のソケット番号は TCPCLOSE しても再利用されず、64 に達すると取得できなくなる。1 回の実行で 1 接続 (HTTP/1.1 keep-alive) にし、nuage-cluster の週次の計画 IPL で番号を戻す |
| GDG | MVS 3.8j では世代を作るときに型紙 (モデル DSCB) が要る。`DCB=(NUAGE.USAGE.GDGMODEL,...)` で指定する |
