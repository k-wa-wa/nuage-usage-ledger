# 使用量勘定システム 設計 (たたき台)

クラスタの資源使用量を、勘定として記帳・残高管理するシステムの設計である。
現在の日次使用量帳票 (README) を発展させ、このリポジトリで一体として扱う。

## 1. 目的と方針

### 1.1 目的

- namespace・ホストごとに、資源の**割当**と**使用**を記帳し、**残高** (割当の残り) を管理する
- 使用量を共通の単位に換算し、日次で締めて元帳を更新する
- 割当の超過を検知し、通知する

課金はしない。単位は金銭ではなく、資源の換算単位である。

### 1.2 方針

- **勘定系の作法を真似る。** 業務日付、日次締め、元帳の世代管理、複式の仕訳、試算表による貸借一致の検証、統制勘定と補助元帳の照合、端数処理規則の明文化などを、このシステムの規模には過剰と承知のうえで取り入れる。目的は、メインフレームの勘定系の設計と運用を体験し、理解することにある
- 処理はメインフレーム (MVS) の中で完結させる。時刻 (ZTIMER)・データ取得 (REXX)・集計と記帳 (SORT・COBOL)・帳票の印字を MVS が持つ。Linux 側は帳票の PDF 化だけを担う
- マスタ (換算表・勘定・割当) は Git で宣言し、nuage-cluster の mvs-config で MVS に届ける。MVS の中の手作業での変更はしない

## 2. 決定事項

| # | 論点 | 決定 | 理由 |
| :-- | :-- | :-- | :-- |
| 1 | 単位 | 資源ごとの使用量を、共通の換算単位 **RU (Resource Unit)** に換算して記帳する | 残高を 1 つの数で表せる。換算と端数処理が勘定系の 10 進演算の題材になる |
| 2 | 換算表 | 仮の値で始め、Git で管理する (3 章) | 値の妥当性は運用しながら調整する |
| 3 | 勘定の単位と番号 | namespace・ホスト 1 つにつき 1 勘定。勘定番号は「区分コード 3 桁 + 連番 7 桁」 | 現在の帳票の 1 行と同じ粒度にする |
| 4 | 割当 | **週次**。毎週月曜の業務日付で、勘定ごとの割当額を一括で記帳する | 日次より変化を細かく追え、月次より残高の推移に意味が出る |
| 5 | 残高不足 | マイナス残高を許し、**超過通知**を出す | 使用は実際に発生した事実であり、記帳を拒否できない |
| 6 | 処理日 | 毎日処理する (休日の概念は持たない) | 営業日カレンダーは後の題材にする |
| 7 | 端数処理 | RU の 1 未満を**切り捨てる** (明細行ごと) | 規則を 1 つに決めて明記することを優先する |
| 8 | 置き場所 | このリポジトリで一体として扱う。名前は `nuage-usage-ledger` (旧 nuage-usage-report) | 使用量の帳票と勘定は同じ業務領域である |
| 9 | オンライン | KICKS (CICS 互換) の 3270 画面で、勘定の残高と仕訳を照会する。**照会専用**とし、締めの後に作る元帳の写し (照会用ファイル) を読む | 勘定系の「昼はオンライン照会、夜にバッチで更新」の分け方を真似る。元帳を更新するのはバッチだけになり、バッチとオンラインの更新の競合が設計上起きない |
| 10 | 月次締め | 月が替わったら前月を締める。前月の仕訳を**仕訳保存ファイル**に移し、勘定ごとの月末残高を残し、勘定元帳を印字する | 日次の仕訳は 35 世代 (約 35 日) で消える。記帳の根拠を残し続けるには、日次とは別の保存の単位が要る。月次で保存用に退避するのは勘定系の作法でもある |
| 11 | 古い仕訳の照会 | オンラインの勘定照会は、仕訳保存ファイルの仕訳も含めて、記帳を始めた日からの全仕訳を出す | 画面で残高の根拠を最初まで遡れるようにする |

## 3. 単位と換算表

| 資源 | 使用量の単位 | 換算 (RU) |
| :-- | :-- | :-- |
| CPU | コア時間 | 1 コア時間 = 10 RU |
| メモリ | GB 時間 | 1 GB 時間 = 1 RU |
| 通信 | GB | 1 GB = 2 RU |
| ストレージ | GB 日 | 1 GB 日 = 0.5 RU |

- 使用量は小数第 2 位まで持つ (現在の固定長レコードと同じ `9(7)V99`)
- 換算額 = 使用量 × 換算率。資源ごとに計算し、**1 RU 未満を切り捨てる**。勘定の日次使用額は、切り捨て後の資源ごとの額の合計とする
- 換算表は有効開始日を持ち、改定しても過去の記帳は当時の換算率のまま残す

## 4. 勘定の体系

### 4.1 勘定科目 (総勘定元帳)

| 科目コード | 科目 | 意味 | 残高の向き |
| :-- | :-- | :-- | :-- |
| 1100 | 割当原資 | 割り当てた RU の出どころ | 借方 |
| 2100 | 利用者勘定 (統制勘定) | 各勘定の残高の合計。明細は補助元帳 (4.2) が持つ | 貸方 |
| 4100 | 使用実績 | 使用した RU の累計 | 貸方 |

### 4.2 補助元帳 (勘定マスタ)

利用者勘定の明細として、勘定ごとの残高を持つ。

| 項目 | 内容 |
| :-- | :-- |
| 勘定番号 | 区分コード 3 桁 + 連番 7 桁 (例: `100-0000001`) |
| 区分コード | `100` = K8S (namespace)、`200` = HOST (NixOS ホスト) |
| 名称 | namespace 名またはホスト名 |
| 週次割当額 | 毎週月曜に記帳する RU |
| 残高 | 割当累計 − 使用累計 (マイナスもある) |
| 最終取引日 | 最後に記帳した業務日付 |

勘定の追加・廃止・割当額の変更は、Git の勘定マスタ定義で宣言する。

### 4.3 仕訳

| 取引 | 借方 | 貸方 |
| :-- | :-- | :-- |
| 週次割当 | 1100 割当原資 | 2100 利用者勘定 (該当勘定の残高を増やす) |
| 日次使用 | 2100 利用者勘定 (該当勘定の残高を減らす) | 4100 使用実績 |

### 4.4 検証 (締めのたびに行う)

- **試算表の貸借一致**: 全科目の借方合計 = 貸方合計
- **統制勘定と補助元帳の照合**: 2100 利用者勘定の残高 = 勘定マスタの残高の合計
- **未登録の利用者**: 使用量があるのに勘定が無い namespace・ホストは、記帳せず未登録リストに出す

不一致があれば、そのジョブを異常終了させ、その日の締めを確定させない。

## 6. 処理

### 6.1 日次締め (ジョブ LEDGER。毎日 06:10、ZTIMER から起動)

```
 GET      REXX : 業務日付を読み、次回処理日から前日までの使用量を VictoriaMetrics から取る
                 前日まで処理済みなら RC 4 で終わり、後続はすべて飛ばす
 TRANGEN  COBOL: 換算表で RU に換算し (1 RU 未満切り捨て)、使用の取引を作る
                 期間内の月曜ごとに、全勘定の週次割当の取引を作る
                 勘定の無い利用者は未登録リストに印字する
 SORT          : 勘定番号・日付・種別の順
 POSTING  COBOL: 勘定マスタ定義・旧勘定マスタ(0)・取引を勘定番号で突き合わせて記帳する
                 定義にあってマスタに無い勘定は開設し、週次割当額を 1 回分 (開設時割当) 記帳する
                 試算表の貸借一致と、統制勘定と補助元帳の照合を検証する (不一致なら RC 16)
                 勘定残高明細・超過通知・試算表を印字する
 CMASTER / CJOURNAL / CGL / CBIZDATE
               : 確定。ここまでがすべて RC 0 のときだけ、新しい世代と次回処理日を書き込む
 MONTHLY       : 月次締め (ジョブ LEDGMON) を内部リーダで投入する。LEDGMON は最後に
                 照会用ファイルの作成 (ジョブ LEDGINQ) を投入する
```

- POSTING は業務日付を書き直すとき、19 桁目から後 (最終月次締め月など) を旧業務日付から写して残す。日次締めが書くのは次回処理日と最終締め日だけである

- POSTING までの成果物は一時データセットに作り、最後の確定ステップでまとめて書き込む。検証に失敗した締めは何も確定しない
- 止まっていた日があっても、GET が次回処理日から前日までをまとめて取り、日付順に記帳する (遡り処理)
- 失敗しても業務日付は進まないので、同じジョブを再実行すればよい
- 初回 (業務日付が空) は前日から始める。GET の `START=YYYY-MM-DD` で始める日を指定できる

### 6.2 日次使用量明細 (ジョブ USAGERPT。毎日 06:00)

元帳とは別のジョブとして、前日の使用量そのものを帳票にする (GET → SORT → COBOL)。

### 6.3 照会用ファイルの作成 (ジョブ LEDGINQ。締めの後)

締めの後、月次締め (LEDGMON) の最後のステップが LEDGINQ を内部リーダで投入する。月次締めをしない日も、月次締めが失敗した日も投入する。勘定系の「オンラインの開局準備」にあたる。

```
 INQBLD   COBOL: 業務日付から照会基準日 (最終締め日) を取り、管理レコードを作る
                 勘定マスタ (0) をそのまま写す (勘定番号の順なので並べ替えない)
                 仕訳保存ファイルの全世代と仕訳の全世代 (どちらも GDG の基底名で連結) に、
                 勘定番号 + 反転した日付・連番のキーを付ける
                 仕訳の世代のうち、最終月次締め月までの日付のものは読み飛ばす (保存済みのため)
 SORT          : 照会用仕訳をキーの順に
 LOAD     IDCAMS: 照会用ファイル (KSDS) を消して定義し直し、REPRO で入れる
```

- 照会用ファイルは元帳から作る写しであり、いつ作り直してもよい。手で作り直すときは `S RUNJOB,M=LEDGINQ,L='NUAGE.USAGE.JCLLIB'`
- 締めとは別のジョブにする。照会用ファイルを作れなくても、締め (元帳の確定) は成功として残す
- KICKS で照会中の利用者がいると、照会用ファイルを消せずに失敗する (RC 8)。消せなかったときは定義・読み込みをせず、照会中の利用者は前回の写しを見続ける。利用者がサインオフ (KSSF) してから流し直す。失敗は他のジョブと同じく MvsJobFailed で知らせる
- 月次締めの直後は、同じ月の仕訳が仕訳保存ファイルと仕訳の世代の両方にある。最終月次締め月で読み飛ばすことで、照会用仕訳に同じ仕訳が二重に入らない
- 照会用仕訳は月に約 2 トラックずつ増える (勘定 18、1 勘定あたり月に約 35 件の見積もり)。いまの割り当て (30 トラック、増分 15) で当面足りる

### 6.4 月次締め (ジョブ LEDGMON。日次締めの後)

月が替わって前月の日次締めがすべて済んだら、前月を締める。日次締めが確定するたびに LEDGER が投入し、締める月が無ければ何もせずに終わる。

```
 MONSEL   COBOL: 業務日付から締める月を決める (下を参照)。締める月が無ければ RC 4 で終わり、
                 後続 (確定まで) を飛ばす
                 締める月がすでに仕訳保存ファイル (0) にあれば RC 16 で終わる (二重の保存を防ぐ)
                 仕訳の全世代 (GDG の基底名で連結) から、締める月とそれより後の日付の仕訳を抜き出す
 SORT          : 勘定番号・日付・連番の順
 ACCTLDG  COBOL: 前月の月末残高 (0)・勘定マスタ (0)・抜き出した仕訳を勘定番号で突き合わせる
                 総勘定元帳 (0) から統制勘定 2100 の残高を取る
                 勘定ごとに、前月繰越 + 当月の増加 (割当) - 当月の減少 (使用) = 次月繰越 を求める
                 照合する (下を参照。不一致なら RC 16)
                 勘定元帳・月次残高表を印字する
                 締める月の仕訳を仕訳保存ファイルの形で、月末残高を新しい世代の形で一時データセットに作る
 CHIST / CMONBAL / CBIZDATE
               : 確定。ここまでがすべて RC 0 のときだけ、仕訳保存ファイルと月末残高の新しい世代と、
                 業務日付の最終月次締め月を書き込む
 ONLINE        : 照会用ファイルの作成 (ジョブ LEDGINQ) を内部リーダで投入する (前のステップの RC によらず)
```

| 論点 | 決定 | 理由 |
| :-- | :-- | :-- |
| 締める月 | 仕訳の全世代のうち、最終月次締め月より後の日付で最も古い年月を、締める月の候補とする。候補の年月が次回処理日の年月より前なら締める (例: 10/31 を締めると次回処理日は 11/01 になり、10 月を締められる) | 月末の日付を計算せずに「その月の日次締めがすべて済んだ」を判定できる。最終月次締め月が空 (初回) でも同じ規則で最初の月が決まる |
| 1 回に締める月 | 1 か月だけ。遡り処理で 2 か月以上たまっていたら、翌日の締めの後に次の月を締める | 処理を単純にする。抜き出す仕訳は遡り処理で作った世代に入っており、その世代は 35 日残る |
| 前月繰越 | 前月の月末残高 (0) の次月繰越。初回 (月末残高が空) や、その月に開設した勘定は 0 | 前月の月次締めの結果をそのまま引き継ぐ |
| 対象の勘定 | 勘定マスタ (0) の全勘定のうち、開設日が締める月の末日以前のもの。その月に仕訳が無い勘定も出す (前月繰越 = 次月繰越) | 元帳は取引の無い月も繰越を示す |
| 照合 | 勘定ごとに、次月繰越 = 勘定マスタ (0) の残高 - 締める月より後の仕訳の影響。勘定マスタは次回処理日の前日までの残高であり、締める月より後の仕訳を戻すと月末の残高になる | 月次で積み上げた残高と、日次の補助元帳から逆算した残高という別の道筋の結果を突き合わせる。日次締めの直後に月次締めをすれば「後の仕訳」は無く、勘定マスタと直接一致する |
| 統制勘定の照合 | 総勘定元帳 (0) の 2100 利用者勘定の残高 - 締める月より後の仕訳の影響の合計 = 次月繰越の合計 | 日次の試算表と同じく、統制勘定と補助元帳 (ここでは勘定元帳) の一致を月末の時点で確かめる |
| 件数の照合 | MONSEL が抜き出した締める月の件数・金額 = ACCTLDG が仕訳保存ファイルの形で書いた件数・金額。締める月より後の件数も合わせる | 抜き出しから保存までに仕訳が落ちていないことを確かめる (コントロールトータル) |
| 二重の保存 | 締める月 (またはそれより後の月) がすでに仕訳保存ファイル (0) にあれば、MONSEL が RC 16 で止める | 確定の途中 (仕訳保存ファイルを書いた後、業務日付を書く前) で失敗すると、最終月次締め月が進まないまま月が保存される。そのまま流し直すと同じ月を 2 回保存してしまう。止まったら、仕訳保存ファイル (0) と月末残高 (0) を消すか、業務日付の最終月次締め月を手で進める |
| 仕訳保存ファイルの並び | 勘定番号・日付・連番の順 | 勘定元帳を印字する順と同じにする。日次の世代 (日付の順) とは並びが違う |

- 日次締め (LEDGER) と月次締め (LEDGMON) は、どちらも業務日付を `DISP=OLD` で割り当てる。MVS はジョブの開始から終了まで、割り当てたデータセット名を排他で押さえる (ENQ) ため、2 つのジョブは同時には動かず、照会用ファイルの作成 (LEDGINQ。業務日付を `DISP=SHR` で読む) も、締めの途中の状態を読まない
- 失敗しても最終月次締め月は進まないので、LEDGMON を流し直せばよい (`S RUNJOB,M=LEDGMON,L='NUAGE.USAGE.JCLLIB'`)。流し直さなくても、翌日の日次締めの後に同じ月を締め直す
- 照会用ファイルの作成 (INQBLD) は、仕訳保存ファイルに最終月次締め月より後の月があれば (上の確定の途中の失敗)、その月までを保存済みとみなして日次の仕訳を読み飛ばす。照会用の仕訳が二重にならない

## 8. オンライン照会 (KICKS)

KICKS (CICS 互換のトランザクション処理。導入は nuage-cluster) の 3270 画面で、勘定を照会する。
TSO で `EXEC 'NUAGE.USAGE.CLIST(LEDGER)'` を打つと KICKS が始まり、最初に勘定一覧が出る。`KSSF` で TSO に戻る。

### 8.1 トランザクション

| ID | プログラム | マップセット | 内容 |
| :-- | :-- | :-- | :-- |
| `LLST` | LLSTPGM | LLSTSET | 勘定一覧。勘定番号の順に 15 件ずつ、区分・名称・残高・状態を出す。超過 (マイナス残高) の行は明るく表示する。S を付けて Enter で勘定照会へ |
| `LBAL` | LBALPGM | LBALSET | 勘定照会。1 つの勘定の残高・割当累計・使用累計・開設日・最終取引日・状態と、仕訳を新しい順に 10 件ずつ出す。年月を打つと、その月の末日以前の仕訳から出す |

| キー | LLST | LBAL |
| :-- | :-- | :-- |
| Enter | S を付けた勘定を照会する。または打った勘定番号から一覧を出す | 打った勘定番号を照会する (`1000000005` でも `100-0000005` でもよい)。年月 (`YYYYMM`) も打つと、その月の末日以前の仕訳から出す |
| PF7 / PF8 | 前 / 次の 15 件 | 新しい / 古い仕訳の 10 件 |
| PF5 | - | 勘定一覧 (いまの勘定から) |
| PF3 / CLEAR | 終える | 終える |
| PA1-3 | 同じ画面を出し直す | 同じ画面を出し直す |

- 疑似会話型 (pseudo-conversational) で作る。画面を出したら `RETURN TRANSID(...) COMMAREA(...)` で終わり、次の入力で同じトランザクションが新しく始まる。続きに要る状態 (勘定番号・頁・頁ごとの先頭のキー) は COMMAREA で受け渡す
- 2 つのトランザクションの間は `XCTL` で移り、COMMAREA には勘定番号 (10 バイト) だけを渡す
- どちらの画面にも照会基準日 (どの締めの写しか) を出す
- 勘定照会の頁送りは、COMMAREA に頁ごとの先頭のキーを 50 頁分 (仕訳 500 件。1 勘定で約 14 か月分) まで持つ。それより古い仕訳は年月を打って出す。年月を打ったときの先頭のキーは「勘定番号 + 反転した `YYYYMM99` + `000000`」で、そこから前へ読むとその月の末日以前の仕訳が新しい順に出る。頁はそこを 1 頁目として数え直す
- 年月を打ったときの先頭の残高 (8.3) は、いちばん新しい仕訳から先頭のキーの手前まで読み進め、仕訳の影響を戻して求める

### 8.2 照会用ファイル

| 論点 | 決定 | 理由 |
| :-- | :-- | :-- |
| 勘定マスタ | 勘定マスタ (0) をそのまま KSDS (キー = 勘定番号) に写す | 勘定マスタは順編成の GDG で、キーで引けない。レコードの形を変えなければ、変換の誤りが起きない |
| 照会基準日 | 照会用勘定マスタの先頭に管理レコード (キー `0000000000`) を置き、最終締め日を持たせる | 画面に「いつの締めの写しか」を出すため。マスタファイルに管理レコードを置く昔ながらのやり方を真似る |
| 仕訳 | 仕訳保存ファイルと仕訳の全世代を、キー = 勘定番号 + 反転した日付 + 反転した連番 の KSDS にする | 仕訳は締めごとの GDG で、先頭が日付のため勘定番号で引けない。日付と連番を反転させると、勘定の中で新しい仕訳ほどキーが小さくなり、前から読む (READNEXT) だけで新しい順に出せる |
| 仕訳の範囲 | 記帳を始めた日からの全仕訳。月次締めの済んだ月は仕訳保存ファイルから、まだの月は仕訳の GDG から取る (6.3) | 照会用ファイルは毎回元帳から作り直す写しにする。足し込み型の累積ファイルは、作り直しや締めの再実行で二重になるおそれがある。どちらの出どころから取るかは最終月次締め月で決め、二重にしない |
| 作り方 | 締めの後に、別のジョブ (LEDGINQ) で毎回作り直す | 6.3 を参照する |

### 8.3 仕訳の後の残高

勘定照会の仕訳の行には、その仕訳の後の残高を出す。勘定マスタの残高 (= いちばん新しい仕訳の後の残高) から、
新しい順に仕訳の影響を戻していく。仕訳の影響は複式の科目から決める。

| 仕訳 | 残高への影響 |
| :-- | :-- |
| 貸方が 2100 利用者勘定 (割当) | + 金額 |
| 借方が 2100 利用者勘定 (使用) | - 金額 |

次の頁の先頭の残高は COMMAREA に入れて渡す。

### 8.4 KICKS の表とライブラリ

KICKS の利用者ライブラリの形で `NUAGE.USAGE.KICKS.V1R5M0.*` を持ち、CLIST(KICKS) に `TSOID(NUAGE.USAGE)` を渡して連結させる。
表は接尾辞 `LG` で作り、`SIT(LG)` で選ぶ。

| 表 | 内容 |
| :-- | :-- |
| SIT (KIKSITLG) | 使う表 (PCT・PPT・FCT は LG、ほかは KICKS の 1$)、端末制御 2$ (MVS 3.8 向け)、最初のトランザクション (PLTPI) = LLST |
| PCT (KIKPCTLG) | トランザクション ID とプログラム。LLST・LBAL と、KICKS 自身のもの (KSGM・KSSF など) |
| PPT (KIKPPTLG) | プログラムとマップセット。この業務のものと、KICKS 自身のもの |
| FCT (KIKFCTLG) | ファイル (DD 名)。INQMAST・INQJRNL と、KICKS 自身のもの (KIKTEMP・KIKINTRA・KSDB) |

表・マップ・プログラムは、ビルドジョブ LEDGBLD がアセンブル・コンパイル・リンクする。
資材が変わると nuage-cluster の mvs-config が流す (`nix build` の `build/LEDGBLD`)。手で流すときは `S RUNJOB,M=LEDGBLD,L='NUAGE.USAGE.JCLLIB'`。

## 11. 実装で分かったこと

| 項目 | 内容 |
| :-- | :-- |
| COBOL の WRITE | ブロック化した出力ファイルは、WRITE の後で記録域が次のレコードに移る。WRITE したレコードを後で参照すると S0C7 (データ例外) になる。レコードは WORKING-STORAGE で組み立てて `WRITE ... FROM` で書く |
| COBOL-68 | 部分参照 (`X(1:1)`) が無い。FD に 01 を複数書くと同じ記録域を別の形で見られる |
| 権限とカタログ | 利用者指定なしのバッチ (内部リーダ経由) は既定の権限で動く。マスターカタログは更新できず、GDG の世代のカタログ登録に失敗する (`NOT CATLGD 2`)。しかも確定ステップの RC は 0 のままである。NUAGE の別名をユーザーカタログ UCPUB000 に向け、RAKF で `NUAGE.USAGE.*` に ALTER を許して解決した (`mvs/rakf`) |
| HTTP の接続数 | BREXX のソケット番号は TCPCLOSE しても再利用されず、64 に達すると取得できなくなる。1 回の実行で 1 接続 (HTTP/1.1 keep-alive) にし、nuage-cluster の週次の計画 IPL で番号を戻す |
| GDG | MVS 3.8j では世代を作るときに型紙 (モデル DSCB) が要る。`DCB=(NUAGE.USAGE.GDGMODEL,...)` で指定する |
| VSAM | PUB000 には共用の VSAM 空間が無く、KSDS は `UNIQUE` で定義する必要がある (無いと `IDC3025I INSUFFICIENT SUBALLOCATION DATA SPACE`)。`UNIQUE` と `REUSE` は併用できないため、作り直すときは DELETE / DEFINE する |
| VSAM の削除 | KICKS の利用者が CLIST で割り当てている間は、IDCAMS の DELETE が失敗する (`IDC0551I ... NOT DELETED`、RC 8)。待たずにすぐ失敗するため、照会用ファイルの作り直しは「失敗したら何も変えない」形にした |
| KICKS の COBOL | MVS/CE の COBOL コンパイラはリンクリストに無い (`SYSC.LINKLIB`)。KICKS の PROC (K2KCOBCL) のコンパイルのステップに STEPLIB を足す。JOBLIB にすると別の IFOX00 (アセンブラ) が呼ばれて表のアセンブルが失敗する |
| KICKS の前処理 | KIKPPCOB は領域を多く使う。ジョブに `REGION=4096K` が無いと S878 になる |
| KICKS の起動 | KICKS は起動直後、TSO の `***` の後に PA2 を送って最初の画面を描き直させる。プログラムは PA キーを再表示として扱う。また最初のトランザクション (PLTPI) にも COMMAREA が渡ることがあるため、初回の判定は COMMAREA の長さで行う |
| KICKS の CLIST | CLIST(KICKS) が KICKS に渡す引数は 100 文字までで、PCT・PPT・FCT・PLTPI を個別に渡すとあふれる (`PARM FIELD TRUNCATED`)。SIT にまとめて `SIT(LG)` だけを渡す |
| KICKS の STARTBR | 最後のキーより大きいキーで STARTBR すると、NOTFND 以外の状態が返る。NOTOPEN・DISABLED (ファイルが無い) だけを「照会用ファイルが無い」とし、ほかは「該当なし」として扱う |
| BMS マップ | KICKS のマップ生成 (KIKMG) は `TERM=` を注釈として扱い RC 4 を返すため書かない。長いリテラルは継続行にせず、項目を分ける |
| COBOL の警告 | `EXEC COBUCG,COND=(0,NE)` はプロシージャの全ステップの COND を置き換える。コンパイルが警告 (RC 4) で終わると実行のステップ (GO) も飛ばされる。桁あふれのおそれの警告 (`IKF5011I-W`) も RC 4 になるため、受け側の桁を足りるようにしてコンパイルを RC 0 で終わらせる |
| 編集の PIC | 浮動の符号 (`---,--9`) は、最初の `-` が符号の位置で数字にならない。13 桁を出すには `-` を 13 個 (`--,---,---,---,--9`) 書く |
